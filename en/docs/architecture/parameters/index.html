Parameters Reference

The 221 automatable APVTS parameters, their types, ranges, identifiers, and behaviors.

Metulifer exposes 221 automatable parameters managed by a single juce::AudioProcessorValueTreeState (APVTS). All parameters are thread-safe and read atomically by the audio thread with zero real-time heap allocations or mutexes.

Naming Convention

Parameter identifiers follow a strict naming scheme:

  • Global parameters: tempo
  • Modulation parameters: lfo<M>_<param> (where M is 1 or 2)
  • Voice / sequence parameters: seq<N>_<param> (where N is from 1 to 6)

1-based indexing for hosts

In the APVTS and your DAW automation list, sequences are labeled seq1 through seq6, and LFOs are lfo1 and lfo2. Internal C++ logic iterates over 0-based indices.

State Not Stored in APVTS

Some data structures are purposefully segregated from the APVTS:

  1. Step bitmasks (32 steps × 6 sequences = 192 steps): Stored in a separate steps ValueTree child to prevent cluttering host automation lists with binary toggles.
  2. Virtual modulation patch cables: Stored in the mod ValueTree child.
  3. Modulation Matrix: All 540 bipolar matrix intersections are persisted in matrixTree (matrix) and kept lock-free in std::atomic<float> modMatrix.
  4. Current playhead positions and gate triggers: Dynamically calculated per audio block.
