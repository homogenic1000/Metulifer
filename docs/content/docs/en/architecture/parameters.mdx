Metulifer exposes **209 automatable parameters** managed by a single `juce::AudioProcessorValueTreeState` (APVTS).
All parameters are thread-safe and read atomically by the audio thread with zero real-time heap allocations or mutexes.

## Naming Convention

Parameter identifiers follow a strict naming scheme:

- **Global parameters**: `tempo`
- **Modulation parameters**: `lfo<M>_<param>` (where `M` is 1 or 2)
- **Voice / sequence parameters**: `seq<N>_<param>` (where `N` is from 1 to 6)

<Callout type="info" title="1-based indexing for hosts">
  In the APVTS and your DAW automation list, sequences are labeled `seq1` through `seq6`, and LFOs are `lfo1` and `lfo2`.
  Internal C++ logic iterates over 0-based indices.
</Callout>

## 2. LFO Modulators (10 parameters = 2 × 5)

Each LFO provides 5 parameters:

| Parameter ID | Display Name | Type | Range | Default | Description |
|---|---|---|---|---|---|
| `lfo<M>_rate` | `LFO<M> Rate` | Float | 0.1 – 20.0 Hz | 1.0 Hz | Frequency (skew 1.0 Hz at center) |
| `lfo<M>_wave` | `LFO<M> Wave` | Choice | Sine, Saw, Square, Triangle | Sine | Modulator waveform shape |
| `lfo<M>_offset` | `LFO<M> Offset` | Float | −100 – +100 % | 0 % | Continuous DC bias offset |
| `lfo<M>_depth` | `LFO<M> Depth` | Float | 0 – 100 % | 100 % | Modulation intensity sent to patch cables |
| `lfo<M>_enabled` | `LFO<M> Enabled` | Bool | On / Off | Off | LFO power switch |

## 3. Per-Sequence Parameters (198 = 6 × 33)

For each sequence `seq<N>` (where `N` runs from 1 to 6):

### ADSR Envelopes (8 parameters)

Each voice features two distinct oscillators with independent ADSR envelopes:

| Parameter ID | Type | Range | Default | Description |
|---|---|---|---|---|
| `seq<N>_a1` / `seq<N>_a2` | Float | 0.1 – 2000 ms | 5 ms | Attack duration (skew 0.3) |
| `seq<N>_d1` / `seq<N>_d2` | Float | 0.1 – 2000 ms | 200 ms | Decay duration (skew 0.3) |
| `seq<N>_s1` / `seq<N>_s2` | Float | 0 – 100 % | 70 % | Sustain level |
| `seq<N>_r1` / `seq<N>_r2` | Float | 0.1 – 5000 ms | 300 ms | Release duration (skew 0.3) |

## State Not Stored in APVTS

Some data structures are purposefully segregated from the APVTS:

1. **Step bitmasks (32 steps × 6 sequences = 192 steps)**: Stored in a separate `steps` ValueTree child to prevent cluttering host automation lists with binary toggles.
2. **Virtual modulation patch cables**: Stored in the `mod` ValueTree child.
3. **Current playhead positions and gate triggers**: Dynamically calculated per audio block.
